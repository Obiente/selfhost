# Existing application capability audit

This audit covers the original 27 app recipes, independently of newly added catalogue entries. It records native contracts rather than assuming every app has the same authentication, database or management API. Each row links the upstream source used to identify applicable capabilities.

All rows support portable Compose lifecycle, logs and metrics. Existing-image discovery is available for all 27; discovery itself does not grant write access. Configuration changes do not automatically restart the app. Database bindings apply to fresh deployments and do not migrate an existing database.

## Remaining engine work

- Native JSON/INI files with source precedence and schema-aware validation where apps do not accept equivalent environment settings.
- Authenticated Socket.IO workflows for Uptime Kuma, with explicit ownership, replay protection and uncertain-write recovery.
- Provider-specific and app-specific account/group provisioning. Generic OIDC settings alone cannot safely choose an administrator for every app.
- Full browser IdP sign-in tests for each new mapping. Native settings and container readiness tests do not verify real provider login.

These are tracked gaps, not reasons to hide applications or imply their features are unsupported upstream.

Database adapters validate their supported TLS modes. Nextcloud single-image, Homarr and Vaultwarden currently permit MySQL/MariaDB bindings only with explicit `disable` TLS on a private network; unsupported encrypted source modes are refused until the adapter supports their native certificate options. Gitea, Forgejo, Grafana, Gotify and Memos use verified TLS when enabled. This is configuration support, not an automatic migration of an existing SQLite installation or a claim that every external TLS topology has been tested.
